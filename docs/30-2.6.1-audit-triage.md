# 2.6.1 audit follow-up

The supplied full audit targets 2.5.3 (`3392aaf`). Rechecked against the
released 2.6.0 tree (`ff5b129`), not against the report's historical lines.

## Changes in this patch

- **PLAT-1:** quick-capture notification PendingIntent request codes now use a
  separate range from the timeline widget. Both intentionally retain their
  existing intents, flags and capture modes. A source contract checks all four
  notification codes against the widget's codes.
- **UI-3:** the photo annotator's Clear all asks before removing drawings and
  text. Cancel/dismiss leaves marks, draft and undo/redo untouched. Confirming
  keeps the existing clear behavior; the dialog explicitly says it cannot be
  undone. No change to crop, drawing or output encoding.
- **AI-1:** `deleted` and `commitments` reads wait on the existing action card,
  with specific Persian/English questions. This applies even to an explicit
  question because each action reads a category rather than a word-limited
  result. Approving performs the read once; declining shares nothing from it.
  Search, tag/thread relevance checks, global AI opt-in, write confirmations
  and disclosure logging are unchanged.
- **DES-1:** selected filter text uses `nexReadableOn` against the composited
  12% accent wash. Pill fill, border, accent dots, geometry and behavior stay
  the same. Tests cover light/dark, Comfort and a pale custom accent.

## Additional useful findings, outside this four-fix patch

These paths remain present in source; they need focused reproduction before
claiming device symptoms or choosing a broader implementation.

| Finding | Current evidence | Priority/scope |
| --- | --- | --- |
| PLAT-3: interrupted APK download does not resume automatically after process death | `UpdateService._downloadApproved` starts false in memory; `resumeInterruptedDownload` returns before inspecting the `.part` file. Tapping Download again still resumes. | Useful updater reliability follow-up. Persist consent for the exact approved version; do not auto-download an unrelated release. |
| PLAT-2: update-ready notification inherits a quiet channel | `DownloadService` first creates `nex.updates` with LOW importance; Dart's update-ready notice reuses it with high per-notification importance. Existing Android channel importance takes precedence, subject to user settings. | Separate progress/ready channels, preserving user notification choices; verify on Android. |
| AI-2: image chats use the text timeout | `_postChat` always uses the 90-second `_textTimeout`, while other media paths allow three minutes. | Media-aware timeout follow-up; a slow image response can expire earlier than intended. This is not proof that every image chat fails. |
| DATA-1: sync pull can overwrite a pending local edit | `SyncClient.sync` leaves rejected pushes pending, then `_applyPage` calls `applyRemoteNote`, whose UPDATE unconditionally marks the row synced and replaces content. | Release gate for future sync. Android currently offers no pairing/sync settings flow; do not describe this as general local-note loss in the shipping app. |

## Corrections to the report

- **CORE-1:** Nex-exported one-item checklists already import as checklists
  using explicit Markdown metadata. Do not remove the conservative heuristic
  for arbitrary unmarked one-line Markdown.
- **MOD-2 / REL-2:** CLAUDE and the modules README already name the five live
  modules. Paused modules remain Soon; this patch does not enable them.
- **UI-1 / DES-4:** Flutter 3.35.5 declares `chevron_left` and `chevron_right`
  with `matchTextDirection: true`. Adding manual mirroring would double-flip
  them. This does not certify every calendar's previous/next semantics.
- The custom HTTP endpoint finding is a Windows concern: shipping Android
  already blocks cleartext traffic. Broad module deduplication, OOM predictions
  from file size alone and undocumented performance percentages are not
  immediate, reproduced defects.

## Validation

- Flutter 3.35.5 / Dart 3.9.2, UTC; 119 targeted client tests and 33 UI tests
  passed, including assistant read approval, photo clear/cancel/redo, Persian
  RTL/dark dialog, PendingIntent identity, version/bundle parity, source-size
  and UI consistency guards, tag selection and contrast variants.
- Full client and UI package analysis: no issues.
- No Android device/emulator run or APK build was performed here. The native
  identity regression is covered by the source contract, not a shade/widget
  instrumentation test.
