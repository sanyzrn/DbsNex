# Uniform collapsed timeline cards — 2.6.2

## Final display contract

- All collapsed note kinds share `nexCardHeightFor(context)`. Captions, reminders,
  urgency and attachments never add height. Compact and Standard have two rows;
  Readable has three. Font and accessibility scaling still determine the envelope.
- The preview occupies the entire content width, independently of status marks.
  Text wraps naturally at that width; no column, inline placeholder or manual
  line breaking reserves space for marks. Short text starts at the top so that
  a bottom overlay does not cut through a vertically centered first line.
- A status overlay sits at the bottom-start of the content: left in English,
  right in Persian, following the interface rather than individual paragraphs.
  Existing reminder, urgency and attachment marks pack in that order with no
  empty slots. The solid background hugs the marks plus a small gap; a 16 dp
  outward fade blends back into the preview. It uses the exact card surface,
  including the selected-card tint, rather than a hard-coded white fill.
- The overlay masks the whole last-row height behind its marks, avoiding stray
  tops of letters above the icons. Other lines retain the same width and layout
  as an unmarked card. Readable therefore keeps all three preview rows.
- Reminder text compacts first. At narrow accessibility sizes, marks can wrap
  inside the existing envelope rather than clipping a clock or attachment count.
  Full schedules remain available to semantics and tooltips.
- A text caption occupies the last preview row in secondary grey, never adding
  height. Expanded cards remain expandable and place marks below the content.
  Show in full measures the full preview width, and remains available when the
  overlay can conceal the last row or secondary content. Its accessibility
  fallback uses the same localized status measurements as the rendered card.
- Note data, reminders, AI, capture, theme selection and unrelated settings are
  unchanged. No new dependency or API request is introduced.

## Validation

Flutter 3.35.5 / Dart 3.9.2, matching the project pin:

- **74 UI tests** across seven focused suites cover every note type and all eight mark combinations,
  captions, all densities, RTL/LTR, light/dark, selected surfaces, narrow cards,
  nonlinear scaling and linear scaling through 3.2. Regression checks compare
  paragraph bounds and every visible text box with/without marks, assert all
  three Readable rows, packed mark order, safe short text, clocks and counts.
- A rendered-pixel test verifies that the solid surface actually hides the
  preview and the trailing edge fades, in both directions.
- **17 client reminder and expansion tests** pass without weakening their
  schedule, clock or count expectations. Full UI analysis and formatting run.
- **Two real-font renders**, English/light and Persian/dark, are visually
  inspected across all densities, with and without captions and reminders.
- Android/device validation and the complete GitHub workflow remain separate
  from these local focused checks.

The previous side-rail implementation was replaced because it could consume
nearly half the paragraph width. Widening that rail to repair reminder clocks
made the preview narrower still. The overlay removes that dependency entirely.
