## Nightly stress

[Run 41947971941](https://github.com/sanyzrn/DbsNex/actions/runs/41947971941) tested
`5f4c4b8a2f5fdb05ae8e4b849f59ea7521682870`. The data suite's third shuffle
(seed `4050760232`) failed `a thread is a view: its notes stay on the timeline`;
the client races passed. Raw ISO timestamp ordering placed `.010100Z` before
`.010Z`. The already-merged correction normalizes fractional precision without
rounding microseconds and uses row order for equal instants. The current code
passes that seed and the fixed-time precision regressions. The workflow and its
repeat counts, fail-fast behavior and time limits are retained.

## Toolchain and compatibility

- `.fvmrc`: Flutter **3.47.9**, bundled Dart **3.13.7**. Pure-Dart jobs use the
  same Dart version; all manifests describe the supported minimum. Flutter
  3.44 cannot satisfy the bot's new `meta` constraint because its SDK pins 1.18.
- Both Dart groups are combined at their highest requested constraints. SQLite
  uses the requested `^3.8.0` constraint and resolves to **3.9.0** in both client
  and data, with native build hooks. The 0.6 EOL
  compatibility constraint prevents the old Flutter-specific SQLite plugin from
  returning; its obsolete loader workaround and generated registrations are gone.
- Real APK/AAB checks require a bundled SQLite ELF of the right architecture for
  every Flutter ABI, including the store artifacts. Package id, signer,
  versionCode/previous-ABI, store-permission and publication gates remain intact.
- Archive 4.6 no longer throws on damaged data by default. Every ZIP reader now
  explicitly requests verification and errors. Parsing remains lazy, so backup
  entry bounds still run before ordinary payload extraction. Authentication of
  private ZIPs and rescue/normal-backup distinctions remain enforced.
- `local_auth` 3 uses typed failures and named authentication options. Temporary
  and biometric lockouts, missing credentials/hardware and cancellation retain
  their UI meanings. Background persistence and biometric-only policy are tested.
- TypeScript **7.0.2** performs checks and compilation; **6.0.2's compatibility
  API** remains available to ESLint through Microsoft's supported npm aliases.
  There is no peer-dependency override or disabled lint check. Dotenv is 18.0.9.
- Parking and medicine date fixtures use a fixed local civil time serialized as UTC, rather
  than assuming every runner is in UTC. The same Persian/Gregorian date and
  24-hour assertions are checked in UTC and Asia/Tehran.
- The PDF reader test waits for native image decoding to finish instead of a
  fixed 30 ms sleep; its page, zoom and prefetch assertions are retained.
- SDK API migrations preserve transition alignment, cache distance, ticker mode
  and semantics assertions. The new reorder callback already adjusts the target
  index; the old extra decrement is removed to preserve attachment ordering.
- Lint-driven null-aware elements/initializing formals and SQLite `close()` calls
  follow the upgraded analyzers. No timing budgets, golden tolerance, consistency
  baselines, module rollout or stress checks are relaxed. Windows/iOS stay paused.

Primary migration references:
[TypeScript side-by-side setup](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/#running-side-by-side-with-typescript-60),
[SQLite hooks](https://pub.dev/packages/sqlite3),
[Archive changes](https://pub.dev/packages/archive/changelog),
[local_auth changes](https://pub.dev/packages/local_auth/changelog).
