# Nex 2.6.5 — eleven approved audit fixes

Scope: the eleven user-approved findings from the two v2.6.2 audit reports. Keep existing timeline/card work and the store distribution path. No release tag or merge is part of this change.

1. **Vault backup:** full backups explicitly including the vault now carry a bounded ZIP of its encrypted attachments. The attachment key and bundle SHA-256 are inside recovery-code-encrypted settings, binding the entire file bundle to the authenticated backup. Restore authenticates first, re-encrypts each attachment under the receiving installation's key with fresh ids, and remaps entries/drafts. Plaintext/weak ZIP replacements are refused before trusting settings or attachments. Existing files/key remain intact for the existing undo journal. Version-1 backups remain readable; archives carrying attachments use format version 2.
2. **Vault draft:** draft writes use a separate encrypted, verified record. Legacy embedded drafts remain readable. A revision consumed by an entry save is recorded in the same atomic main-vault write, preventing stale draft resurrection after interruption.
3. **Sync:** a rejected pending local version is copied transactionally, including caption, derived text, tags and attachments, before applying the remote version. The recovery copy is pending and searchable; its pin/manual order/reminder are cleared to avoid duplicate alarms and pin-limit overflow. Concurrent tags are unioned and republished; a pending local tombstone is retained. Push acknowledgement compares the pushed revision/time in SQL so it cannot clear a newer in-flight edit.
4. **Updater:** persist available release metadata and exact approved version; hydrate the badge after restart; resume only a matching approved partial/completed installer. Metadata/approval/check timestamps are installation-local and excluded from portable settings. All check/download/resume entry points reject store installations and `NEX_STORE_BUILD=true`. Progress uses `nex.updates.progress` (low), completion `nex.updates.ready` (high); no store build/manifest rules were changed.
5. **Scheduled notes:** automatic and manual arrivals cancel arrival alarms, schedule existing preference-controlled enrichment and refresh timeline/local nudge. Reminder picking awaits the complete draft flush.
6. **Android file export:** if opening a document with `wt` fails/returns null, try `w`, then copy using the existing failure handling.
7. **Widgets:** immutable list snapshots are volatile; stale row requests use bounded lookup in timeline/recap; timeline item-id lookup is also bounded.
8. **Image chat:** all three cloud wire formats use the existing 3-minute media deadline for image payloads. Text chat retains 90 seconds. Cancellation behavior is retained.
9. **Vault attachments:** lazy messages/password/card lists, display-sized bitmap decode, reuse of the same plaintext open/share cache path until lock cleanup, cancelled audio state/position subscriptions and guards against late or duplicate playback starts.
10. **Receipt cleanup:** sweep only the root and explicitly owned `media/recurring/` directory against note/attachment/live commitment references and the existing one-hour grace period. Preserve profile/other directories, links, live and fresh files. Malformed commitment metadata fails closed.
11. **Tags:** batch trash/outbox tag reads, and resolve only incoming tag ids in bounded queries rather than scanning the entire tag table once per note.

## Validation

- Focused data tests cover local conflict preservation, tags/caption, remote and local deletion, replay, receipt grace/reference/profile/symlink protection, repository behavior, sync timeouts and archive round trips.
- Client tests cover full service backup/restore with a real encrypted attachment, transfer to a new device/key, invalid/missing attachments, legacy/separate draft recovery, lazy 1,000-message rendering, scheduled notes, update persistence/consent and existing reminder/update behavior.
- Store guards pass with Bazaar/Myket installer identities and separately with `--dart-define=NEX_STORE_BUILD=true`, including an unknown installer and cached direct-download consent. No HTTP requests occur.
- Cloud tests simulate elapsed time across 90 and 180 seconds for OpenAI/Gemini/Anthropic, alongside existing provider and connection tests.
- Changed Dart libraries and tests are analyzed with fatal infos; widget layouts, changelog consistency, version and source-size guards are checked.

Native Android compilation/device checks remain pending: this environment has no Android SDK. Before publishing, verify save-to-cloud provider fallback, rapid widget refresh, download process death/resume and completion notification behavior on a device. No unrelated dependencies or store manifest/build settings are changed.
