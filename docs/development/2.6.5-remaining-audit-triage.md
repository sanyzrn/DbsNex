# Remaining v2.6.2 audit findings, rechecked for 2.6.5

The eleven approved fixes are implemented and documented in `2.6.5-audit-fixes.md`. The four prioritized items below and the equivalent module helpers are now implemented in the follow-up, documented in `2.6.5-follow-up.md`. The remaining corrections still apply.

## Worth doing

1. **Missing-media recovery backup (DATA-02):** `NexBackupArchive.createFromSnapshot` still refuses the entire backup when any referenced file is absent, including a trashed note. This is deliberate fail-closed behavior covered by a test, so do not silently weaken it. Add an explicit rescue/partial backup with an authenticated missing-file inventory and a visible warning, preserving the strict complete-backup path and restore validation.
2. **Failed native search-model initialization:** `NexEmbedder.engineFor` creates an engine and calls `initialize()` without closing that newly created engine if initialization throws. `close()` only knows the assigned `engine`, so that object is outside cleanup. Close the created object on failure and preserve the original error. Actual device memory impact has not been measured.
3. **Sync responsiveness (ARCH-02 / BUG-09, narrower scope):** network waits in `SyncClient` still run under the database command queue. A slow multi-request sync can delay capture and reads. Move/yield network work while keeping page writes transactional and conflict handling intact. Sync has no normal Android setup screen, so this is conditional on using/configuring sync, not a general shipping capture defect.
4. **Vector cache work (PERF-05):** `put` and `remove` invalidate `_centre`; `_settleCentre` recomputes the corpus sum and all row projections. Useful at large corpus sizes, but the suggested running sum alone removes only the first pass. Benchmark before/after, retain ranking equivalence and address projection work too; no actual device slowdown is claimed from code inspection alone.

## Useful later

- Module helpers have real identical groups (four identical adaptive segment files and several form-draft/record-bundle families), but draft guards/store states are not all byte-identical. Consolidate exact families gradually with module tests; do not blindly delete the reported 28 files.
- Inline Persian/English `nexLabel` strings still bypass ARB. Centralize these before adding another UI language. Shared input styling and remaining stock components can be migrated incrementally, without redesigning unrelated screens in a reliability patch.

## Corrections and low-confidence claims

- `NexDailyNudgeReceiver.java` already imports `android.Manifest`; BUG-07 is not present.
- The repeated `TextPainter`/nested-layout claim targets the old 2.6.2 card implementation. Current icon-only halos use a different layout; do not alter the recently corrected card geometry based on those line numbers.
- Backup compression is already in a separate `Isolate.run`. Provider enrichment/embedding commands are already outside the serialized queue. The broad claim that all backup/AI work blocks capture is inaccurate; sync/import still deserve separate consideration.
- LinkReader has early-return streams it could explicitly cancel, but both shipping callers close the owned client in `finally`. The report's persistent socket-leak impact is overstated. Explicit cancellation is small hardening, not a leading defect in today's call graph.
- A process death also kills Dart; it does not leave the same Dart future waiting forever. Picker callback fields are not persisted, but the alleged hang needs an activity-only recreation/cached-engine reproduction before choosing a lifecycle migration.
- Portrait lock exists. Removing it is a product/layout decision requiring tablet/foldable QA; it does not automatically prove that the desktop shell will activate on Android.
- Urgency is already spoken by the card's parent semantics. Adding another child announcement can repeat it; do not treat `ExcludeSemantics` alone as a proven accessibility bug.
