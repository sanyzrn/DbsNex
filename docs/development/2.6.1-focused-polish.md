# Six scoped improvements for 2.6.1

## Scope and decisions

1. **Smart Summary:** keep the existing approved, bounded habit projection,
   privacy switch, fingerprint, cache and refresh schedule. Pending reminders,
   unfinished work and useful notes get the factual line budget first. Remove
   the forced reservation of a habit line. Action-oriented local text excludes
   routine daily completions and combines at most two weekly milestones into
   one acknowledgement, bounded by the selected word budget. Report can retain
   fuller progress; model prompts put completed goals after useful actions and
   explicitly leave Custom under the user's instruction. No sample-specific
   habit names or extra model requests are introduced.
2. **Paste:** use the existing 300 ms enter duration and smooth in/out curve,
   with opacity and the 48 dp width progressing together in both directions.
   Keep the editor/controller/focus node and Paste implementation intact.
   Reduced motion uses the existing duration resolver.
3. **Translation:** the existing language bar is one ink target and opens the
   same picker from the source, target, blank space or arrow. The arrow retains
   its visual widget but does not create a second tap or semantics target.
   Loading still disables selection. Dimensions, jobs and translation state
   are unchanged.
4. **Cards:** ordinary previews share their height with status marks. A real
   inline placeholder reserves only the necessary end-of-text space; no text
   is painted beneath a badge. The old `_Tucked` shader/fade was reviewed and
   intentionally not restored. Preserve paragraph directions and grapheme
   boundaries, shorten reminder text first, keep counts and reminder semantics,
   and avoid double-scaling badges under nonlinear accessibility text sizes.
   Captions, checklist/link structures, voice durations, custom previews and
   expanded cards retain their separate space, as requested.
5. **Memory:** add a row at the end of the Intelligence settings category and
   a simple opt-in page. Use the existing `ai.userIntroduction` text and setter;
   move that field out of Assistant. `ai.memory.enabled` defaults false only
   when absent; `ai.memory.consentSeen` records the first accepted explanation.
   Both switches preserve the saved text and all other choices. Each assistant
   request resolves `effectiveAiMemory` from the current switches. No learning,
   conversation analysis, database or additional API call is added. Assistant,
   Smart Summary and Memory rows are disabled while Intelligence is off. The
   existing locally generated Report, if already selected, still works without
   AI; disabling a settings entry does not erase that choice.
6. **Disclosures:** remove only the duplicate Intelligence-screen row, its
   divider/navigation and unused import. The Security entry and
   `DisclosuresScreen` are retained and tested.
