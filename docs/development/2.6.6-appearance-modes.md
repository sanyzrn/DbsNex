# 2.6.6 — appearance modes

## Delivered behavior

- Light stays on the existing Nex renderer. Night is the former Dark renderer.
- Dark uses the supplied Soft UI reference's neutral roles: page `#141821`, card
  `#1C212C`, nested surface `#252B38`, main ink `#E4E8F1`, muted ink `#98A1B5`.
  Small blue text, selected fills and filled-button text have separate roles
  so the new palette does not reduce contrast.
- System follows OS brightness: existing Light or new Dark.
- Existing stored `appearance.theme=dark` reads as Night without rewriting
  preferences or backups. Explicit new Dark stores `soft_dark`; Night stores
  `night`. Both are included in portable-preference validation and round trips.
- `nexThemePresetsAvailable=false` pauses the gallery. `themePreset` remains the
  stored selection; `effectiveThemePreset` returns `classic` for rendering.
  All 15 presets, motifs and gallery code remain. The row is dimmed and disabled,
  and the assistant cannot overwrite the stored palette while it is paused.
- Custom accent and Liquid Glass remain independent controls. Glass retains its
  material when enabled; high contrast still uses solid, visible boundaries.
- Four mode choices are offered in Appearance and onboarding. Assistant theme
  actions understand Night too. Same-brightness Dark/Night switches participate
  in root rebuilding and the existing reduced-motion-aware theme transition.

## Renderer boundaries

`nexDarkTheme` remains the previous public component renderer, with
`nexNightTheme` as its explicit alias. The application routes new Dark through
`nexSoftDarkTheme`. This keeps existing Light/Night component snapshots intact.
Minimal material removes decorative borders/elevation, retaining focused/error
fields, selected state semantics, and high-contrast outlines. Selected choice
cards use tonal fills in ordinary Dark and visible outlines in high contrast.
The onboarding button label follows its actual filled-button foreground rather
than assuming the page's primary-container roles are always the button colors.

To restore the gallery later, review its presets against both dark renderers,
then change the single availability flag. Do not clear saved palette IDs or
custom accent/glass preferences. Older clients that validate only the old theme
enum need upgrading before they can restore new-mode settings backups.

## Follow-up: Soft Light and OLED Night (unreleased)

The original 2.6.6 decision above was intentional: app Light and Night kept
legacy rendering to preserve visual baselines. In the follow-up, the **app**
selects dedicated `nexSoftLightTheme` and `nexOledNightTheme` renderers from
the supplied Soft UI demo, while the older public `nexLightTheme` and
`nexNightTheme` APIs remain unchanged. Night now uses true black (#000000),
charcoal cards (#0E0F12) and softer text (#D9DDE6); Light uses white page,
#F4F5F8 cards and #14171C text. Both opt into the existing minimal surface
behavior: decorative borders and shadows are removed, not functional outlines.
Soft Dark keeps its surface colors and minimal material; its primary text is
softened from #E4E8F1 to #D9DDE6 for consistency with Night. Secondary text
remains #98A1B5. Storage, saved appearance wire values, accents, Liquid Glass
and high-contrast behavior stay independent. Library golden baselines still test
the legacy renderers; app-mode and contrast tests cover the new routes.
