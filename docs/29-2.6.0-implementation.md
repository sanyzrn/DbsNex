# Nex 2.6.0 — implementation and acceptance

Owner-approved scope: all eight items below. Implement in dependent groups, preserving current behavior outside the requested changes. Baseline: published 2.5.4, main c71f7dfa1c2f623e6549a41c9b8ac16f76581af8. Shared working branch: codex/2.0-polish. No SDK/dependency upgrade, PR creation, merge or release is included.

## Scope and acceptance

1. **Pull reversal** — consume reverse drag to close the refresh strip before allowing timeline offset to advance, including a single uninterrupted down/up gesture. Preserve subthreshold cancellation, successful refresh, normal scrolling, multitouch and existing pull visuals. Use a local drag-consumption solution, not notification suppression or global physics changes.
2. **Refresh completion** — replace NexRefreshSheen with a subtle, original Nex completion treatment. Keep pull visuals. No card movement, flash or perpetual animation. Distinguish success, failure and cancellation; success effects must not run on failure/cancel. Respect reduced motion.
3. **Untagged** — a virtual filter after every real tag, also after newly created tags. Exclusive with real-tag selection; combinable with note type/reminder filters. All clears every filter. Same pill treatment; no fake database tag.
4. **Capture Paste** — Note, Checklist and Link show the existing Paste icon only for a completely empty editor. Fade it out on entry/paste and reclaim its whole column; restore on empty. Preserve editor/controller/focus/caret/keyboard and icon dimensions/location.
5. **Recurring cards** — balanced directional padding; actions vertically centered against the whole card; group countdown and exact time with clear hierarchy. Verify check action in code and clarify its existing meaning, without changing recurrence logic. Long text, RTL/LTR and touch targets remain supported. Reference upload/01-1000050294.png.
6. **Note captions** — use the existing independent caption field for text notes, with add/edit. Original body remains primary on timeline; optional caption is secondary beneath it. Include caption in search and AI source/context without regressing other media types.
7. **Urgent** — durable independent state, toggled from detail More Actions and hold menu. Small coordinated flame in the reminder/attachment indicator row only; no card/type-icon/color/border/background/order/filter/search or Pin behavior changes. Menu switches to remove urgency.
8. **Daily Nudge** — reuse notification infrastructure; useful local bilingual text based on actual urgent notes, upcoming/recent overdue reminders, unfinished checklists and upcoming active commitments. No network requests. Use only a valid fresh summary when AI AND home summary are enabled, otherwise local. Nudge off cancels daily alarms. Five supplied Persian empty-library prompts and natural English equivalents rotate without consecutive repetition. A quiet nonempty library is not an empty library. Exclude completed/stale/inactive data. Rebuild on relevant changes, one notification per local day at the chosen time, preserve permissions/privacy and other reminders.

## Design decisions

- The refresh controller supplies physics only to its timeline scrollable. Reverse travel consumes raw pull distance before forwarding a remainder. Completion uses two fine accent strokes gathering into Nex's dot inside a 24 dp repaint boundary, with stable child layout/state. Failure has an error-coloured pull accent and the existing error banner; cancellation retracts quietly; reduced motion skips completion motion.
- Urgency is local metadata, like Pin. Database schema version 2 adds a default-false column and preserves it through the legacy type-check rebuild. Toggling never touches content, FTS, revision, timestamps, Pin or sort order. It survives database backups and app restarts; JSON export and server sync retain their existing local-organisation policy.
- A text caption uses the existing field, editor, FTS indexing and sync. The primary preview remains intact; one quiet caption line is secondary. Text-note AI source and recap input include it.
- Daily Nudge reads a bounded snapshot in the database worker and prepares text in a separate isolate. It uses 60 candidates per independent category, with nearest one-off reminders separate from old repeat start dates. Finished checklists, archived/deleted notes, old one-off reminders, stale unfinished lists and paused recurring items are excluded from current facts. Explicit Urgent stays active until the user removes it. An existing quiet, archived or retained-trash library gets review prompts rather than first-use prompts.
- Android has one private native daily receiver and one alarm/notification ID, preserving the existing notification channel, exact-alarm permission fallback, app-lock visibility and other reminders. The existing notification plugin's repeating-time API recalculates from the current day, so mixing factual one-shot alarms with a future repeating fallback would permit duplicates. The native policy instead stores a dated 32-day local text plan and persistent per-date delivery receipts. It selects and rotates text while Flutter is closed, then arms only the next selected local clock time. After the dated horizon, neutral rotating prompts continue without stale factual claims until Nex refreshes the plan.
- Background note/commitment/habit Done actions invalidate dated text before persisting their existing actions. Native delivery also rechecks Nudge, AI, home-summary, habit-sharing and app-lock preferences. A source-matched summary must be no more than one hour old on the delivery date. Turning off AI or the home summary immediately selects local text; turning off habit consent discards mixed summary reuse. No provider request is made by planning or delivery.
- Data and relevant preference writes debounce and serialize plan rebuilding. Completed checklist changes work while detail stays open, without requiring navigation. Disabled Nudge avoids planning on unrelated data writes. Unchanged input does not reschedule; a native day receipt prevents a second daily notification after time changes, toggles, reboot or duplicate broadcasts.
- The target is the repository's Android release. The paused iOS path retains its existing notification backend with a neutral local fallback; the Android native delivery policy is not claimed as an iOS feature.
