# 2.5.4 — verified follow-up to the 2.5.2 audit

The owner requested investigation and implementation of the valuable findings,
not wholesale adoption of the report. Baseline: merged 2.5.3, source commit
`3392aafcce8ad6b961e4fabd2749e23a6c9d4733`. Its release was already running;
these changes belong to 2.5.4. No database schema migration is introduced.

| Finding | Verification and resulting change |
|---|---|
| R1, restore version | Integrity alone accepted future schema versions. The read-only probe now also checks `user_version` and raises `NewerLibraryException` before either archive or bare-SQLite restore swaps live files. Tests preserve the original database bytes and media. This is a compatibility guard, not evidence of a higher schema version already shipping. |
| R25, Markdown import | The exporter writes frontmatter but the generic parser treated it as text and UUID filenames as titles. New exports use marked metadata with JSON-escaped title/tags. Text/checklist import restores metadata; legacy envelopes are recognised conservatively, ordinary or malformed YAML remains content. Imported notes receive new identities. Complete archive import remains the way to preserve media, reminders and other library relationships. |
| A1/A2, consent | Master AI opt-in already works and defaults off; the legacy `cloudAiOptIn` field being unused does not prove unconsented uploads. Existing saved defaults are retained. Actual gaps were assistant dictation/image paths ignoring effective capability switches; these now check at capture/attachment and send time, and the microphone updates while the sheet is open. |
| P1, root rebuild | Every preference notification rebuilt MaterialApp and both themes. A value signature now limits that work to root-rendered appearance/locale/calendar/onboarding settings and actual lock-state changes. Haptics, secrecy and habit-access side effects still update directly. Feature widgets retain their subscriptions. |
| P3, diagnostics | Logging synchronously read and rewrote the file. Writes now use asynchronous I/O and one error-tolerant per-file queue, including separately constructed logger instances. Forwarding error handlers is still immediate. Diagnostics exports flush pending writes first. Redaction and retention bounds are preserved. |
| P5, search | Keyword hits were already displayed before semantics; the report overstated network blocking for those hits. Old empty-query results and requests during typing were real gaps. Local search still debounces at 150 ms; semantics waits a further 300 ms and requires three Unicode code points. Superseded queries are invalidated immediately and cloud embedding transport is aborted through an optional query-only adapter interface. Background note indexing is unaffected; on-device computations can finish but their stale results are discarded. Existing query-vector cache remains. |
| T1/T2, CI | Tools and portable contracts were missed by path filtering. They now select the relevant checks; tools also select Android script validation. The final gate requires success for every selected job and always-on guard, accepting skips only for unselected areas and explicitly paused platforms. Scripts have regression tests. |
| D1–D3, docs | Module availability in CLAUDE and README was stale. They now name all five available modules and refer to the rollout registry; the roadmap records the current baseline without discarding historical decisions. |

## Corrections and limits

- `deleted` is a read of Recently Deleted; actual `delete` waits for user
  confirmation. Do not introduce a second confirmation flow based on A8.
- `version_test.dart` already checks the newest named changelog release against
  the source version. The release preflight added before this audit follow-up
  also checks the actual checked-out source before expensive jobs.
- Rejecting every skipped CI job would break legitimate selective verification.
- File length, counts of string literals and whole-root rebuilds are evidence
  about code shape, not measurements of frame latency or proof of a crash.
  Broad file splitting, catalogue migration and tablet redesign need separate
  work; no performance percentage is claimed here.
- No P0/data-loss claim from the static report is accepted without reproducing
  its path. Restore/share-window coordination and unreleased sync findings
  remain candidates for separate review, not silently claimed as fixed.

Validation belongs in commit history and CI. Before release, run
`python3 tools/release_notes.py --tag v2.5.4` on the exact release source and
start a fresh release run after merging. Do not reuse the 2.5.3 run.
